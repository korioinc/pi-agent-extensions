# Runner pool

One generation-scoped registry owns a configured number of lifecycle-held slots (default 3), origin-scoped volatile answers, cancellation and drain. Admission atomically reserves a slot and startup/invocation deadlines before preparation. Full capacity returns `busy`; draining generations return `unavailable`, without discovery or queuing. Degraded health is diagnostic: blocked runs retain their own slots while other free slots remain usable.

For logical agents, `RunOptions.commit` synchronously commits the reserved run through Registry before Pool enables progress or schedules execution. The callback receives only the run ID and stop handle, never a result promise or an external gate to resolve. Pool checks authority before publication, then rechecks authority, cancellation and the original absolute startup deadline before execution. Synchronous progress consumers can stop dispatch; failed or pending delivery never owns completion. Submissions without logical options retain synchronous initial progress.

A thrown commitment value produces `RunSubmission.admissionFailure` alongside the existing completion handle, including when the thrown value is falsy. The executor never starts, and the same safe settlement pipeline owns capacity release. Registry clears uncommitted foreground references and rolls back local metadata before releasing its logical lane; its later finalizer does not mutate a newer reservation. Registry awaits the result before returning the original rejection. Committed history still finalizes only after resource safety, and unexpected executor rejection still retains unsafe ownership. No commitment/finalization callback is stored on a terminal run.

Phases: `preparing`, `running`, `safeguarding`, `cancelling`, `settling`, `blocked`, `terminal`. Progress is separate from the terminal completion promise. Five-second hard-stop grace can mark blocked/degraded, retaining slot and foreground promise. Eventual safe settlement releases capacity once; no timeout, TTL or force-unlock substitutes for safety.

Turn, invocation and tool-deadline exhaustion enter `safeguarding` once. Pool closes ingress, gives existing work a 30-second finish window, then aborts the ordinary-work signal. The hard cancellation signal remains separate. Runner may begin one summary after SDK idle and operation drainage; Pool caps it at 60 seconds within the first trigger’s absolute 90-second window. Hard cancellation always preempts this phase. Startup expiry cannot enter safeguard. `RunView.safeguard` records the first reason and summary state; it cannot turn incomplete execution into success.

Settlement requires completed preparation, execution, delegated accounting and cleanup. A still-pending executor resolves directly from `blocked` to `terminal`; it never re-enters `settling`. Safe preparation failures retain admitted `runId`. Unexpected executor rejection or resource-close failure remains blocked with no later settlement continuation. Stop intent during cleanup cannot rewrite an already-settled outcome.

Terminal retention keeps only a minimal live authorizer, never the admission/finalization options or progress callback. Registry shares one small authority owner across a logical agent's runs, so later input fences also constrain earlier retained answers without retaining histories or parent adapters through Pool. Idle and closed logical owners detach their foreground adapters; an accepted follow-up supplies fresh adapters. One unreferenced Pool timer expires terminal answers even without later queries. It never expires active/unsafe ownership and is removed when no terminal answers remain or drain completes.

Optional submission `RunIdentity` stores only the selected agent, copied and frozen at admission. Missing internal metadata stays absent. Authorized ID/no-ID inspect, progress, final and cancel projections copy identity without exposing tasks or observation. Duplicate identities do not affect admission, ordering, authorization or cancellation; `runId` remains the per-run control key; a separate `agentId` identifies continued conversation.

`inspectActivity(caller)` is a TUI-only authorized projection in Map admission order. It adds the run's bounded error and latest assistant-text tail, bounded to 512 UTF-16 code units without splitting a surrogate pair. The tail is replaced by existing partial/final output updates and pruned with the run; it is not part of tool summaries, progress or final payloads. Controller sanitizes and fits errors and previews at render time. No extra model requests, accumulated transcript or independent retention cache is added.

`OutputBuffer` applies append/replacement updates to the bounded result prefix, UTF-8 byte count and detached preview tail. Ordinary appends account only for new text, including surrogate pairs split across updates; after truncation, the prefix stops growing while the tail keeps advancing. Native corrections and final settlement replace the projection once. The Pool never retains a full unbounded response or calls back into Session to render it.

Pool owns phase/stage timestamps, monotonic elapsed times and executor status. Runner reports fixed stages; Budget reports pending child-tool/provider-request counts, including codemode’s nested child calls from its promise ledger. Inspect snapshots are origin-scoped, bounded and observational. Only ID-specific inspect includes `activity`: `providerRequests`, actual-tool `toolStarts`, separate `codemodeStarts` admission totals and the last eight SDK tool calls with 128-byte names and neutral states. SDK-rejected calls can appear without a Budget tool admission. This volatile history excludes arguments, results, raw errors, work internal to delegated parent tools and prompts; progress, final/cancel responses and no-ID lists omit it. Blocked diagnostics report `await_owned_work` while the executor can still settle, or `containment_required` after rejection. These are guidance, not permission to release or retry. Zero counts never prove safety. Terminal durations freeze; repeated stop requests retain the first stop time.

Private run observations store the first bounded prepared model/thinking selection and replace absolute child-model usage snapshots. Only authorized ID inspect clones them; they are not part of RunView/progress/cancel/final results or no-ID listings. No message means `not_observed`, a real zero-usage message means `observed`, and invalid numeric totals mean `unavailable`. Final Settlement reconciles only previously observed usage; the Session’s initial zero accumulator cannot invent an observation. This copy never participates in parent billing or cleanup decisions. Optional `modelTokenBudget` is a cloned Runner Budget projection, not a Pool judgment or accumulator. It includes the configured limit, last valid observed total when available, and observation/exhaustion status only in owner ID inspect.

Retain at most 32 terminal answers for one hour from completion, each 256 KiB UTF-8-safe with truncation metadata. Active/blocked ownership never expires. Authorization requires current generation, originating parent session, stable workspace filesystem identity and a branch containing the latest logical-agent input fence. AgentRegistry owns in-memory logical history across runs until explicit close or generation shutdown, with no idle expiry; Pool run results remain volatile. Closed-agent tombstones retain their separate one-hour limit. Idempotent drain stays pending until owned work is safe.

`handoff(caller, runId)` prunes and authorizes before returning a fresh reference projection. Only safe terminal results with nonempty text qualify, including failed/cancelled partial results. It copies a UTF-8-safe excerpt bounded by `LIMITS.handoffBytes`, outcome and separate source/excerpt truncation flags, never usage, diagnostics, raw errors or capabilities. No await, reservation or source mutation occurs; copied values outlive source expiry.

Each run also owns a bounded active-run FIFO and SHA-256 receipt map. `sendMessage` validates input, authorizes the origin, checks accepted IDs before phase/capacity, and atomically enqueues without awaits. `takeMessages` transitions queued receipts to `injected_not_confirmed` and removes raw pending text. Stop, settling, rejection, terminal completion and generation drain discard unread text. Accepted receipts remain until run pruning, preventing duplicate injection after retry or saturation. Only ID-specific owner inspect projects cloned IDs/states and pending totals; progress, final, cancel and no-ID summaries omit inbox details.

Not a worker service, task queue, workspace lock manager or second cleanup scheduler. See the [architecture overview](../../architecture.html).
