# Session

`ChildSession` in `index.ts` implements the internal SDK session adapter. It uses native `SessionManager.inMemory()` history whose lifetime belongs to AgentRegistry. ChildSession owns the child `AgentSession`, resource loader, extension binding, event subscriptions, parent-model stream bridge and final cleanup sequencing. It is not a second history engine or an independent authentication owner. `ChildTools` in `tools.ts` owns child tool installation and readiness. `resources.ts` installs explicit prompt/skill inputs and request-local context messages. `provider.ts` owns the registered `ParentProvider`; no direct agent stream override remains.

ChildSession stores `ChildTools` before requesting its guarded factories or native session options. The options carry the native activation names and Budget-wrapped ordinary tools. After SDK creation, event subscription and native extension binding, `ChildTools.ready(session)` joins every selected server's readiness and checks the complete declarations. The SDK's first-prompt wait covers direct servers only, so the adapter retains the native codemode readiness hook and selected-server checks. ChildSession needs no native tool names, synthetic readiness event or notification interception. `ChildTools.close()` joins its owned MCP resources; the existing final cleanup sequence still lets an idle SDK dispose while MCP closure remains pending. This internal module adds no SDK session, execution budget or cleanup scheduler.

`ChildSession` marks new native `message_end` tool results for one exempt model request. It clears that marker after the next successful Budget admission. Multiple results do not accumulate credits; user steering and request-local data do not erase pending results. Historical messages in a fresh invocation grant no exemption. Runner Budget still owns the turn ceiling and counts every admitted provider dispatch.

The SDK calls `Provider.streamSimple` through its normal ModelRuntime path. Public `lazyStream` supplies asynchronous setup and event forwarding. The provider reserves each request before awaiting its predecessor, admits dispatch through Runner Budget, and delegates only to the captured parent stream with bounded options. Before dispatch, `ParentProvider.request` checks the authoritative request system text and SDK-replayed effective tool declarations, including `toolsAdded` and dynamic section changes. Parent credentials/options are not copied from the child runtime. Its owned promise includes stream iteration/result, pending fetch acquisition and reader cleanup. Terminal events may arrive before that promise settles; later dispatch waits for safe closure, and a rejected predecessor keeps later requests unsafe. The SDK `end(message)` result fallback is preserved without synthesizing events. Only ChildSession message events accumulate usage. After each assistant message ends, Session sends an absolute cloned total to Runner for owner-only diagnostics. This callback neither adds usage again nor replaces the final accounting path.

The bridge forwards only the SDK's optional `cacheRetention` preference within that allowlist. When unset, the parent provider resolves its native default/environment; the bridge does not force `none`. The session ID comes from the registry-owned child history and survives idle follow-ups. SSE and owned request/reader cleanup remain independent of provider prompt-cache storage. `cacheWarming: "off"` prevents extra maintenance requests without disabling caching on ordinary requests.

`check` is the authority/cancellation guard used by stream events. The separate `checkHistory` callback validates committed native history after `message_end` appends and before Runner admits a provider request. The message callback queues a microtask because the SDK appends after notifying listeners. Integrity and memory-capacity checks do not run for each stream delta; Registry still validates history during final settlement.

`output.ts` owns response evidence: retained useful text, response failure and stop reason, and private replacement evidence. `AssistantOutput.observe` consumes native SDK events without reconstructing the conversation or introducing a stream parser. It batches new text at a 100 ms presentation interval and emits explicit append/replacement updates through Runner. Native `text_delta` events append within the current last text block; new messages, reordered/edited blocks and final authoritative corrections replace the projection. The ordinary append path never joins or measures the full accumulated response. Owned UTF-16 payloads prevent substring references from retaining prior provider snapshots. Thinking, tool-call and unchanged text updates do not rebuild the text projection; streamed and final tool calls still disqualify a private handoff.

Final messages, snapshots, cancellation and safeguard transitions flush pending text immediately. A text-end correction to empty content or an empty error/tool-only final cannot erase pending findings, even if the provider mutates its native content before the timer fires. `AssistantOutput.replaceWith` stages replacement evidence without publishing it. Output owns response validity, including first publication/model failure, final stop reason and tool-call evidence. ChildSession supplies production work and a synchronous execution-safety check; it retains SDK settlement, cancellation, usage and cleanup policy. Output commits nonempty normal-stop text and its response status together only after acceptance and successful publication. Every other exit discards candidate evidence and pending reconciliation while retaining the prior text and failure. Unlike ordinary output, an empty replacement final invalidates its candidate partial. Candidate status is private until committed; incurred usage is never part of this rollback. Closing the owner flushes and clears its timer and text-block references. Full evidence stays in the output owner; Pool maintains only its bounded prefix, byte count and preview incrementally. Provider checks, tool updates, native history and usage accounting keep their existing cadence.

Model context handling belongs to the SDK and selected provider. Session does not serialize history, message events or the request projection to enforce a fixed byte cap; encoded image size is not a context-token measure. SDK estimates are not promoted into a second hard token-admission rule. Native context errors remain failed runs with normal resource cleanup. Automatic child compaction/retries remain disabled. The provider separately bounds inbound wire bytes and serialized provider events at 8 MiB each per request; this is response-processing protection, not an outgoing-context or total-heap limit.

The single package-owned `context` handler takes the active-run FIFO through Runner before an already-scheduled request, then asks Budget for one wrap-up advisory. Additional data is JSON-encoded with owner attribution and no new authority; the wrap-up notice stays last. Both are request-local user messages without replacing policy or tool declarations. Inbox consumption records `injected_not_confirmed`, not dispatch or model-read confirmation. Failed requests never cause automatic reinjection. This supplemental-data path creates no steering task, extra prompt or persistent history entry. Existing provider admission and native context handling still apply.

Runner constructs the handle before awaiting `start()`. Acquired SDK resources remain reachable after partial initialization failures. `initialPrompt` always wraps the actual task in `<subagent_task>...</subagent_task>` and escapes `&`, `<` and `>` as XML text. With handoff, the reference warning and `REFERENCE` JSON come before the task block, explicitly identifying partial/outcome flags and disclaiming authority. The actual UTF-8 serialization must fit `5 * LIMITS.taskBytes + LIMITS.handoffBytes + 4 KiB` before resource acquisition; the multiplier covers the task's worst-case XML expansion. Raw task/handoff caps stay unchanged. Framing never changes system policy, truncates the task or enables prompt-template expansion. The new in-memory history owns this initial reference only for the new session lifetime. `prompt()` runs the prepared task; `snapshot()` returns the last nonempty assistant text, first model error, cleanup errors and child-model usage without exposing the SDK session. Empty tool/error turns do not erase prior partial work; failure remains failure. A final `length` stop reports incomplete failure; an intermediate cutoff followed by normal completion does not itself fail the run. SDK tool start/end events report only name, correlation ID and neutral outcome to Pool through Runner, never arguments or results.

Safeguard uses three separate signals: hard cancellation, sealed ordinary-work admission, and finish-window expiry. `finishWork()` aborts only ordinary SDK execution, clears queued ingress, waits for idle and verifies provider cleanup without closing MCP. After Runner drains its operation ledger, one `summarize()` prompt reuses history with tools and thinking disabled. It also includes the retained partial response as JSON-encoded, potentially incomplete data because provider transforms can omit aborted assistant messages. This data supplies evidence without granting new authority. Budget independently refuses every tool start and a second summary dispatch. Summary output stays private until a nonempty normal stop and safe provider cleanup; failure preserves the prior useful text. Provider options cap this request at the safeguard output/time ceilings, and usage remains cumulative.

Runner controls finalization order: `abort()` → `Budget.drain()` → `close()`. `abort()` starts MCP close and shares one SDK abort operation between cancellation and finalization, but waits only for SDK abort and never caches a no-op before acquisition. After Budget drainage, `close()` joins MCP and provider closure in parallel with SDK shutdown/disposal and removes the abort listener after all owners settle. A pending MCP close cannot retain an idle SDK context. Abort, transport, shutdown and disposal failures remain unsafe; a settled rejected transport cannot disappear merely because Budget removed its completed promise.

`ChildTools` owns `ChildMcp` in `mcp/index.ts`, which supplies selected-only config and owned transports to the public SDK `createMcpExtension`. Child-local `createCodemodeExtension` and `createToolSearchExtension` use that native registry, not parent tools. Binding starts connections; ChildTools joins the native readiness hook and selected-server checks before the first model request. `mcp/transport.ts` retains bounded readers and first-close failures even when SDK cleanup swallows them. Dynamic native registrations and nested calls join Runner Budget; codemode itself consumes neither the actual-tool allowance nor a leaf concurrency slot, while each nested tool call consumes one start. Its authority, cancellation, deadline, output and ownership guards remain active. Native schema/result/resource/refresh behavior replaces the removed custom search/describe/call implementation.

Native MCP shutdown and owned transport closure begin before waiting for SDK idle, so calls waiting on the connection can stop. The SDK shutdown handler joins the same tracked operation without blocking unrelated idle SDK disposal. Its first close promise remains owned through final settlement, including failures. The `mcp_close` stage means SDK cleanup attempts have finished and MCP closure remains pending; it is not proof of safety. Unsafe MCP cleanup retains the existing blocked barrier.

Session receives narrow callbacks for budget checks, model-dispatch accounting, transport tracking and partial output. Runner owns the single pending-work ledger; Session has no execution slots, pool phases, duplicate model/tool admission ledger or force-release path. Runner waits for all owners before returning settlement to Pool.

Owned MCP transports use SDK stdio/SSE framing defaults without a package override (16 MiB in pinned SDK 1.4.0). The HTTP reader separately bounds non-SSE JSON/error bodies to 16 MiB because SDK JSON/text parsing buffers them. Successful SSE bodies share a separate 256 MiB traffic allowance across all requests/reconnects for that selected transport. Exhaustion aborts its controller, prevents later acquisition and retains every existing acquisition/reader until cancellation and release finish. SDK SSE framing, result conversion and model-facing truncation stay native. Discovery's 8 MiB aggregate catalog allowance is independent of tool payload capacity.

`http-resources.ts` owns shared HTTP response cleanup through `HttpResponseResources.acquire`, `wrapBody`, and `close`. Provider uses one instance per request; `McpHttp` in `mcp/transport.ts` uses one per selected transport across reconnects. Each adapter wraps the response body before its tracked acquisition settles. Close rejects later acquisitions, owns bodies arriving late, and terminates outstanding consumer reads while joining raw cleanup. Endpoint validation, traffic counters, signal composition and final completion decisions remain adapter-local; the shared module has no SDK dependency or run-level ledger.

HTTP body cleanup distinguishes a terminal stream error repeated by `reader.cancel()` from a failed underlying cancellation. It observes `reader.closed` before releasing the lock and joins cancellation and pending reads. Only the same original error value is accepted, before any redaction. Consumer cancellation forwards its reason and shares the same cleanup operation as owner close. Cancellation and lock-release failures remain sticky even when the SDK catches them, including a consumer-handled Provider cancellation failure. Normal fetch abort therefore closes an idle notification stream without poisoning run settlement.

`resources.ts` passes `config.systemPrompt`, `appendSystemPrompt: [config.appendSystemPrompt]` and selected-only `skillsOverride` to the native resource loader, alongside the native MCP extension. The preamble is filtered parent policy plus fixed role in append, or optional instruction file plus fixed role in replace. Native SDK rendering supplies the agent body as `<addendum>`, followed by eligible `<skills>`, cwd and `<mcp_servers>` for indirect access. Direct MCP tools use declarations instead of a server catalog. No manual skill formatting or forced final `systemPrompt` return is used. The custom preamble suppresses only the SDK default preamble; native sections remain active. Replace still requires a nonempty agent body.

ChildTools canonicalizes tool metadata with locale-independent name ordering at the native factory seam. `getAllTools` and `setActiveTools` use sorted copies; registered `prepareLoadout` hooks receive sorted copies of `declared`, `callable` and `registered`, retaining native resolver functions and callback binding. This stabilizes codemode's embedded descriptions as well as direct declarations without mutating the SDK registry. The final `before_agent_start` handler selects sorted **live** active names after earlier native readiness handlers, including initial prompts, idle follow-ups and the empty safeguard loadout. This handler remains installed without MCP. Sorting the event's earlier snapshot could omit tools that completed discovery during those handlers. The SDK still renders sections, records necessary deltas, and applies capability removal; the provider never rewrites retained history for cache matching.

Stable inputs therefore avoid ordering-only cache misses. Real policy/schema/tool changes, provider expiry and model limits can still prevent reuse. Request-local supplemental messages are not persisted or replayed for caching. Preserve existing history when adopting this ordering: order alone must not trigger a transcript migration or resurrect a removed capability.

The SDK advertises selected skill metadata only when native `read` or `bash` is selected. A hidden direct reader declaration uses SDK indirect-access wording; `tools: []`, `read_text` alone and arbitrary custom/MCP readers do not qualify. Explicitly selected `disable-model-invocation: true` skills opt in through normalized metadata and keep the same reader gate. Skill bodies and parent package/extension skill catalogs are never preloaded. Startup checks `session.systemPrompt`; the provider repeats the authoritative prompt/declaration budget check after SDK changes on every request.

DefaultResourceLoader uses empty in-memory settings and disables ambient extensions, skills, themes, prompts and context loading; only package-owned factories execute. SDK discovery can still inspect default resource directories; it does not install packages or activate ambient resources. Each spawn starts a new conversation with a separate initial user task; follow-up reuses the safe child history, never parent conversation or credentials. Selected ordinary parent tools retain parent permission hooks; child-local MCP calls are authorized by explicit server selection and do not inherit those hooks. Nested tool usage remains parent-owned; Session accumulates child-model usage only.

Images returned by selected tools reach child models that advertise image input. For text-only models, the SDK replaces image blocks with its image-disabled notice. This follows the resolved child model's capabilities and does not copy parent attachments, alter selected tools or bypass parent tool permission hooks. Per-tool resource guards and native model context handling still apply.

Idle continuation constructs a fresh runtime over the registry-owned in-memory native conversation with current policy/tools, resources and new-run usage. Active `followup_task` uses a run-bound native steering gate, records receipt admission without claiming comprehension, and shares the original budget/deadline. Safeguard, hard stop or settlement closes ingress and discards undelivered queued tasks. Only the bounded safeguard handoff may add a prompt; no task replay or automatic reinjection is issued. Registry, not Session, owns logical identity and in-memory history until explicit close or generation shutdown. Idle history has no time-based expiry; reload, parent-session replacement or exit prevents later reopening. Disk storage is outside the package. No background worker, standalone provider credentials or second conversation engine. See the [Runner contract](../runner/README.md) and [architecture overview](../../architecture.html).
