# Runner

Runner tracks Runtime's `prepareInvocation()` through Budget before constructing ChildSession or
acquiring SDK/MCP resources. Runtime returns validated configuration and an opaque fingerprint;
Runner owns neither body reads nor fingerprint policy. Every execution validates selected skill
bodies, including runs without continuation. Active follow-ups repeat preparation and compare
fingerprints while the session still accepts input. These reads never preload bodies into the prompt.

Pool's `RunControl.check()` invokes the Registry authority check and handles revocation. Runner
uses that same check through Budget; continuation callbacks own history validation and ingress.

Coordinates one admitted invocation. Captures scope/adapters without reading parent policy, resolves the definition through bounded Runtime preparation, then recaptures valid parent state with a prompt only for append. A named invocation carries task, agent and optional handoff reference through fresh Runtime preparation. It never loads the source session or its authorization. Constructs `ChildSession` and controls execution and final settlement. Physical-model selection and definition errors fail before child creation/model dispatch.

`Budget` remains Runner-owned: counted model turns, observational model-dispatch counts, tool output/update limits, actual-tool starts, separate codemode starts and one pending tool/transport promise ledger. Session wraps ordinary tools and every dynamically registered native MCP/codemode/tool_search definition through `wrapTools`; nested codemode calls share these limits. Each run permits 256 actual tool starts and four concurrent leaf tools. Direct and nested calls each consume one start, including admitted calls that later fail. Codemode itself consumes neither allowance; its authority, cancellation, deadline, output and ownership guards remain active. Empty codemode scripts do not spend the actual-tool allowance. The classification is specific to the child-local codemode tool. Session reports through narrow callbacks; it does not own admission, pool phases or a second budget ledger.

Each JSON-serialized update and final result has an independent 64 MiB envelope ceiling. The wrapper uses `JSON.stringify` and counts the resulting UTF-8 bytes after serialization. Each call also has a separate allowance of 4,096 update callbacks and 128 MiB serialized update traffic. The final result never consumes update traffic. SDK `content`, `details` and `structuredContent` stay intact; the wrapper does not coalesce updates, reimplement truncation or infer which updates are deltas. There is no generation-wide result reservation or total heap cap.

After an operation returns, an oversized result is withheld with a recoverable SDK tool error including measured bytes, the limit and guidance against automatic replay of effects. It does not stop the run or relax subsequent admission. An oversized live update, excess callback count or excess traffic still stops the run because the producer may remain active; pending work stays owned until drainage. Model context handling stays with the SDK/provider; Budget imposes no serialized-history/request byte cap or substitute token-estimation gate. Transport and inbound provider-response bounds remain independent.

Model request admission checks authority, cancellation and deadlines. `ParentProvider.tail` serializes each provider owner's requests through transport cleanup; there is no generation-wide provider gate. Requests without a new tool result debit `LIMITS.turns`; exhaustion requests safeguard with `limit_exceeded: model turns` and denies further ordinary dispatch. Session marks the immediate request after native tool results as exempt from that debit, including results accompanied by steering or supplemental data. Every admitted dispatch still increments `providerRequests`. Tool-result processing remains admissible after the last counted turn, but cannot bypass other guards. Active follow-ups share the current budget; idle continuation starts a new invocation and budget.

`Budget.takeWrapUpNotice()` owns one advisory for the remaining counted-turn/tool allowance or positive model-token remainder at most `ceil(limit * LIMITS.wrapUpModelTokenFraction)`. The optional model-token remainder uses observed child totals, not invoice or tool usage; simultaneous triggers do not duplicate it. Runner passes that observation to the Session context adapter. It does not debit the budget, relax hard admission or introduce a Pool phase. Raw dispatch count never triggers or suppresses the advisory; exhausted turns do not suppress tool-result advice. Aborted runs produce none.

SDK-specific construction, prompt composition, binding, stream adaptation, subscriptions, usage collection and disposal live in [`src/session`](../session/README.md). AgentRegistry owns the lifetime of in-memory native history; Runner passes that history to ChildSession for the invocation. Runner does not access `AgentSession` or its internals. The native provider bridge reserves and reports complete request ownership through the existing transport callback; terminal model delivery alone cannot drain that request.

Before finalization, a safeguard run joins `ChildSession.finishWork()` and `Budget.drain()`. Ordinary cancellation leaves MCP/provider owners reusable; provider cleanup must be proven before summary. Pool authorizes the summary window and Budget admits exactly one summary request with no tool starts. ChildSession stages its output privately and commits only a valid handoff. The result stays failed/incomplete even if summary succeeds; explicit token caps and hard cancellation still win.

Finalization order is `ChildSession.abort()` → `Budget.drain()` → `ChildSession.close()`. Abort starts MCP closure without awaiting it, then awaits SDK abort. After Budget drainage, close joins MCP closure, provider safety and SDK shutdown/disposal independently. Every owner gets a cleanup attempt even if another rejects; pending MCP closure cannot retain an idle SDK context. Runner chooses the execution outcome before cleanup, so cancellation during settling cannot rewrite it. Unknown preparation, tool or session cleanup safety rejects settlement and keeps the owning run blocked with its slot and shutdown barrier retained; counts and timeouts cannot force release.

After successful execution preparation and renewed authority checks, Runner sends the immutable Runtime model/thinking selection summary to Pool. Session’s completed-message usage snapshots first reach Pool observation, then `Budget.observeModelUsage` synchronously. `configureModelTokens` fixes the optional cap after preparation and before child creation; different reconfiguration fails. Budget replaces absolute totals instead of accumulating billing. Enabled totals must be nonnegative safe integers and monotonic; invalid totals make the projection sticky-unavailable and stop future admission without throwing from the usage callback. At/above cap, even a final normal response fails while preserving text and usage. Existing first stop reason and cleanup ownership remain intact. Uncapped runs keep prior permissive accounting behavior. Budget owns the `ModelTokenBudget` projection and Pool only clones it for owner ID inspect. Startup failure before any message stays unobserved even when the final snapshot contains zero usage.

Diagnostics report preparation, session startup, execution, abort, operation drain, SDK shutdown, disposal, remaining MCP closure and final safety. Successful cleanup permits one terminal result with bounded text and child-model usage; parent dispatch separately accounts for nested tool usage.

Idle continuation uses the same in-memory native conversation into a fresh runtime/Budget, current configuration and new usage accumulator. Active steering remains owned by the original run and its remaining limits. AgentRegistry owns in-memory history and logical lifecycle until explicit close or generation shutdown. Runner owns no worker scheduler, router or resumable store. See the [architecture overview](../../architecture.html) and [SDK support](../../README.md#sdk-support).
