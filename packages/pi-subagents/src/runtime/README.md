# Runtime

Prepares immutable child configuration after execution or static-catalog admission. Omitted model inherits the complete parent model; an explicit `model: provider/model-id` resolves one exact registered model, preserving embedded slashes. Thinking remains an independent parent-default override. Parent registry retains authentication and OAuth refresh. No live SDK session, transport or UI ownership lives here.

`ResearchSource.scope()` initially captures only workspace, trust and cancellation scope. After bounded definition discovery, `capture()` reads fresh parent policy and borrowed capability catalogs. Preparation rechecks workspace/trust, resolves and clones one selected model, then snapshots only selected ordinary-tool schemas and annotations before any local-tool construction or skill scan can yield. Unselected models and schemas are not deep-copied. Diagnostic stages now check ordinary tools directly after model selection, before skills and instruction-file acquisition. Preparation never executes the selected capabilities.

Optional handoff references are copied into immutable configuration, separate from task and policy. Runtime still resolves the current definition/tools/MCP/model on every invocation. Preflight never accepts or resolves task/handoff inputs.

Execution uses `prepareInvocation()`, which composes `prepareResearch()` with bounded selected-skill body validation and returns `{ config, fingerprint }`. Runtime owns the fingerprint policy; Runner only compares its opaque values. Every invocation validates bodies before child startup, even without continuation. Active follow-ups repeat the same operation before steering. These reads share the existing Preparation budgets, cancellation and handle ownership; they never preload bodies into the model prompt.

Static preflight calls metadata-only `prepareResearch()` with an internal empty task and never executes the returned tool/model capabilities. Normal subagent input validation still rejects empty tasks. Preparation checks raw instruction text, selected skill metadata and ordinary-tool configuration budgets. Preflight reports `rendered_prompt` as unchecked because final rendering requires the SDK session. When skills are selected, it also reports `skill_body_validation` as unchecked. An optional synchronous stage observer supports fixed preflight failure codes without copying validators or parsing raw error text. Prepared config includes prompt mode and the canonical model/thinking selection summary; preflight projects only safe metadata and discards secret-bearing config. Local selected env substitution and root realpath/stat checks are preparation, not connectivity/authentication proof.

## Generation settings

`settings.ts` reads only `<getAgentDir()>/sub-agents.json` at extension load. It validates
`maxConcurrentRuns` as an integer from 1 through 32; absent file/key uses the default 3. Invalid or
unreadable settings fail loading. Nonblocking open is followed by regular-file validation, a 64 KiB
read bound and strict UTF-8 decoding; every acquired handle closes. Settings symlinks still follow
their target, which must pass the same checks. Controller passes capacity to Pool; no runtime resizing or project override occurs. This load is separate from per-invocation preparation. AgentRegistry always owns generation-local in-memory history; disk storage is outside the package. See [memory-only history lifetime](../../README.md#memory-only-history-lifetime).

## Definitions and prompts

Definitions come only from manually created `<getAgentDir()>/agents/*.md` files. Project scanning, source classification and built-in fallback agents are removed; every invocation requires a name. Definitions fail closed: disabled/invalid/duplicate names are unavailable and unsupported semantic fields error. Directory enumeration errors reject the whole scan; definitions already read cannot authorize execution or refresh the catalog while remaining entries are unknown. Only `display_name` and `color` are cosmetic warnings. `skill_add_folders` and `skills: all` are rejected with migration guidance.

Optional `max_model_tokens` must be a positive safe integer. Omission leaves cumulative model tokens uncapped; null, strings, fractions, zero and unsafe integers are definition errors. The configured `AgentDefinition.maxModelTokens` flows unchanged to immutable `ResearchConfig`, definition listings and successful preflight reports. No spawn argument overrides it.

Resolve the definition before mode-specific parent capture. `config.systemPrompt` contains filtered parent policy in `append`, or the optional `prompt_instruction_path` file in `replace`, followed by the fixed subagent role. Replace never reads the parent prompt. `config.appendSystemPrompt` contains the agent Markdown body, which must be nonempty in replace. Relative paths use the definition directory; configured missing/empty/unreadable/oversized/invalid UTF-8 files fail preparation. The path is rejected in `append`. Removed `append_custom` and `prompt_default_instruction` settings produce migration errors.

`index.ts` imports the package-owned role from [`../instructions/subagent.ts`](../instructions/subagent.ts) and includes it once in the custom preamble. Session passes the two prompt fields and selected skill metadata to the native resource loader. SDK rendering owns the order: preamble → agent `<addendum>` → eligible `<skills>` → cwd → `<mcp_servers>` for indirect MCP access. Runtime does not manually format catalogs or compose a final SDK prompt. The custom preamble suppresses the SDK default preamble while retaining native sections. The role does not replace the nonempty body requirement or tool permission checks. Neither mode copies parent conversation or inserts skill bodies into the initial prompt. The actual task remains in a separate initial user message. Tool declarations remain separate and authoritative.

## Selected MCP configuration

`mcp.ts` reads only `<getAgentDir()>/mcp-sub-agents.json` through Preparation when the definition explicitly selects servers. It validates all selected configurations before resolving their env/header credentials. Parent/project MCP files never grant capabilities. Empty selection does no config I/O; unknown/disabled/normalized-colliding selections fail before transport creation. Commands are not executed during preparation. Default exposure is codemode; native deferred/direct/hidden and toolExposure overrides are also supported. Existing explicit deferred remains valid. Server descriptions are preserved for the native child namespace.

`tools.ts` builds per-selection name indexes for callable tools and metadata, preserving the first matching entry and requested order. It filters inherited parent MCP, codemode/search/resource routes and declared aggregators using that fresh metadata. Missing provenance does not broaden inheritance. Only selected schemas and annotations are copied; delegated closures retain the parent dispatcher and signal instead of the capability catalogs. Ordinary parent calls keep their dispatcher hooks and combined cancellation; independent MCP belongs to Session and follows explicit server selection, not inherited permission hooks.

## Explicit skill selection

`skill-sources.ts` discovers local default directories, scoped settings sources and installed local/managed npm/Git package declarations. It ignores parent activation selectors for catalog membership, not project trust or package manifest exclusions. No parent settings writes, package installation, network calls or package-manager subprocesses occur. Unknown dynamic CLI/extension roots and legacy npm installations need explicit local paths; unsupported source syntax or missing configured packages fails clearly.

`skills.ts` reads bounded candidate frontmatter first, matches only explicit names, then rereads selected frontmatter to revalidate metadata without acquiring full bodies. Canonical aliases deduplicate; duplicate selected names keep the first valid skill in existing discovery order and skip later matches. Omitted or empty selection performs no skill discovery in either mode. Selected metadata goes to native `skillsOverride`; explicit selection sets `disableModelInvocation: false`, including skills whose file has `disable-model-invocation: true`. The SDK still requires selected native `read` or `bash` for advertisement and uses indirect wording when the reader's direct declaration is hidden. Empty tools, `read_text` alone and arbitrary custom/MCP readers do not satisfy that gate. Controller removes inherited resource catalogs using structured section identity, including compressed catalogs. There is no parent package/extension skill inheritance exception. Arbitrary policy prose is preserved, not redacted.

`Preparation` owns async traversal, read handles, cancellation/deadlines and budgets: candidate file 64 KiB, aggregate reads 8 MiB, 32 roots, 4,096 entries, depth 16, prompt/configuration 4 MiB, 60-second startup within the invocation deadline. Candidate, selected-frontmatter and execution-body reads share the same accounting. Session checks its native rendered prompt at startup; ParentProvider checks the authoritative system text and effective tool declarations before every dispatch, including dynamic SDK changes. Pending I/O remains owned until handles close; no Promise.race abandons resources. Unknown closure remains unsafe.

Each file read starts with its stat size plus one sentinel byte instead of allocating the full file allowance. A growing file expands that owned buffer geometrically up to the existing 64 KiB plus sentinel ceiling. Only initialized bytes are copied; actual bytes read still consume the shared budget. File validation, frontmatter parsing, full discovery and awaited handle closure are unchanged.

Dot entries and node_modules are skipped; ignore files are not interpreted. Trusted skill symlinks follow canonical targets with cycle detection. This is not filesystem isolation. Parent tool calls still pass through permission hooks and combined cancellation. See [architecture overview](../../architecture.html).
